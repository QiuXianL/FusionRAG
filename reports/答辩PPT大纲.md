## 2. 背景与意义（为什么做）

- RAG 的效果上限很大程度取决于检索：检索错/证据排太后 → 生成更易幻觉
- 现实问题：用户 Query 往往短、模糊；多跳问题需要跨文档“找桥梁证据”
- 目标：让“首位命中”更高（Recall@1 / MRR），降低 LLM 读长与推理成本

## 3. 研究问题与目标（我们要解决什么）

- 研究问题：
  - 如何构建更好的嵌入向量与索引结构，缩短 Query 与证据之间语义差距？
  - 如何在不显著增加工程复杂度的前提下，提升复杂问题的召回与排序？
- 指标：Recall@1/5/10、MRR
- 场景：SQuAD（单跳）、HotpotQA（多跳）

## 4. 总体方案（系统架构图）

- 索引端（Indexing）：
  - 文档分块 → 文档向量（E5）
  - 文档块问题生成 → 问题向量（E5）
  - 聚类去重（减少冗余/噪声）
- 检索端（Retrieval）：
  - 加权融合（文档分 + 问题分）
  - 候选集重排序（关键词覆盖率）
  - 可选：查询扩展（CoT）+ 多查询融合（RRF）

讲稿提示：
- 强调“嵌入方法研究”不是只换 embedding 模型，而是把“索引结构 + 融合策略”一起纳入。

  - 贪心语义聚类去重（削冗余、控噪声）
  - 加权融合 + 轻量重排（更准更稳）

## 5. Baseline：语义嵌入检索

- Embedding：E5-base-v2（query/document 前缀）
- 数据库：文档块向量
- 检索：余弦相似度 Top-K

讲稿提示：
- Baseline 已经很强，但对多跳/桥接证据、关键词约束会有不足。

## 6. 方法一：生成式索引（Generative Indexing）

- 思路：让文档“主动开口说话”
  - 对每个文档块生成若干“潜在用户会问的问题”
  - 将这些问题也向量化并入库
- 直觉：用户问法 ≈ 生成问题 → 更容易召回正确证据块

## 7. 方法二：加权融合检索（Weighted Fusion）

- 目的：平衡“文档语义相似”与“生成问题相似”
- 公式（核心）：
  - 最终分数 = 0.7 * 文档相似度 + 0.3 * 最大问题相似度
- 优点：
  - 生成问题有噪声时不至于干扰过大
  - 生成问题有效时能显著补强召回

## 8. 方法三：智能聚类去重（Smart Clustering）

- 痛点：LLM 生成的问题存在大量语义重复 → 向量库膨胀、分数稀释
- 方法：基于余弦相似度的贪心去重
  - 长度优先保留信息量更大的问题
  - 相似度阈值：报告中给出 0.85（或实验版本 0.90）
- 收益：更小的索引、更少的噪声、更稳的检索

报告引用：
- [RAG_Optimization_Report_V2.md](file:///E:/program/RAG%20-%20当前使用/reports/RAG_Optimization_Report_V2.md)

## 9. 方法四：轻量级重排序（Hybrid Rerank）

- 痛点：纯向量检索对“实体名/指令/关键词约束”不够敏感
- 方法：候选集上引入字符覆盖率信号
  - 新分数 = 0.8 * 语义分 + 0.2 * 覆盖率
  - 仅对语义分 > 0.6 的候选触发
- 收益：兼顾语义泛化 + 字面精确性

## 10. 方法五：Super Brain（CoT 查询扩展 + RRF 融合）

- CoT 查询扩展：
  - 将复杂 Query 拆成多个子问题/等价问法，覆盖“桥接证据”
- RRF 融合：
  - 对多查询检索结果进行倒数排名融合
  - 原始查询更高权重（weight=3.0）
  - Score = Σ(Weight * 1/(k + Rank))

- CoT + RRF 多查询融合：增强复杂问题召回，提升排序鲁棒性

## 15. 总结与展望

- 总结：
  - 检索是 RAG 的地基；本项目围绕“嵌入/索引/融合/重排”做了系统性改进
  - 在多跳场景上取得可量化提升，并形成可运行原型与可复现实验材料
- 展望：
  - 离线索引与增量更新，解决大规模生成式索引耗时
  - 引入更强精排（Cross-Encoder）进一步提升 Recall@1 / MRR
  - 更大规模真实文档库（课程资料/科研文档）落地验证

## 备选页：可能的答辩问答（可打印备忘）

- Q：为什么这算“嵌入方法研究”，而不是只做检索策略？
  - A：我们研究的是“检索可用的向量表征体系”，包含文档嵌入与生成式增强嵌入，并设计融合与去噪，让嵌入在实际 RAG 场景中发挥效果。
- Q：参数 0.7/0.3、0.8/0.2 怎么来的？
  - A：通过多轮小规模对比实验与误差分析确定，目标是在提升多跳召回的同时控制噪声干扰；并在候选集上仅对高相关结果触发重排以避免误提升。
- Q：如果不用 API 或大模型生成问题，怎么办？
  - A：可以训练/微调本地 QGen 模型或做离线批处理；项目已在报告中给出下一步方向。
- Q：中期提到的“问题多样性不足、重复生成”最终如何解决？
  - A：先做关键词抽取作为锚点，再用 CoT 约束生成；随后用余弦相似度贪心聚类去重控制冗余，并用融合权重/重排门槛抑制噪声影响。
