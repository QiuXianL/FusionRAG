# 方案：RAG 检索效果优化

## 诊断

先跑几组测试查清当前瓶颈在哪个环节：

1. **检索命中率** — 搜已知答案的问题，检查正确文档是否在 top-5 中
2. **重排序效果** — 对比重排序前后的排序变化
3. **查询扩展质量** — 检查 DeepSeek 生成的扩展查询是否合理
4. **分块质量** — 检查文档分块是否合理（当前 chunk_size=300，对 3000 字小说是否切太碎？）

## 可能的优化方向（取决于诊断结果）

| 方向 | 当前 | 可能调整 |
|------|------|----------|
| 分块大小 | 300 字符 | 对小说类内容增大到 600-800 |
| 检索候选池 | top_k × 3 | 增大到 top_k × 5 |
| RRF 权重 | 原查询 3× | 调整或去掉 query expansion |
| 关键词检索触发 | 覆盖率 > 30% | 降低阈值，补更多候选 |
| 重排序精度 | BGE-reranker-v2-m3 | 已验证可用，保持 |
| 查重去噪 | 无 | 检索结果去重，避免同一故事多块霸榜 |

## 实施步骤

1. 先跑诊断测试，定位瓶颈
2. 根据诊断结果选定 1-2 个改动
3. 修改代码
4. 对比优化前后效果

## 完成报告

### 诊断结果

| 查询 | 优化前 | 优化后 |
|------|--------|--------|
| 布隆的盾牌 | ✅ 相关但重复 | ✅ 5/5 相关，无重复 |
| 亚索和永恩谁更强 | ✅ 相关但重复 | ✅ 5/5 全部命中故事 |
| 诺克萨斯重要人物 | ❌ 全部不相关 | ✅ 关键词召回生效，部分改善 |
| 亚托克斯背景故事 | ✅ 结果1命中 | ✅ 结果1完美命中 |

### 识别到的瓶颈

1. **重复块霸榜** — 同一故事不同切块或相同块挤占 top-5
2. **候选池太小** — top_k×3 不够覆盖关键词补召回的候选
3. **关键词分数太低** — 0.7 的初始分无法与向量结果竞争

### 改动

| 改动 | 值 | 说明 |
|------|-----|------|
| 候选池 | top_k×3 → top_k×**5** | 增大召回范围 |
| 关键词分数 | 0.7 → **0.85** | 让关键词结果有竞争力 |
| 向量去重 | 新增 | 前 100 字指纹去重 |
| 最终去重 | 新增 | 重排序后再次去重 |

文件：[smart_retrieval.py](src/smart_retrieval.py)，改动约 15 行。

### 与计划差异

计划中考虑调整分块大小、RRF 权重等，诊断后发现瓶颈不在那里。实际改动更精准。
