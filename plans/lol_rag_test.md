# 方案：跑通 LoL 宇宙关系分析

## 目标

用现有 RAG 系统测试 LoL 英雄背景故事的关系分析能力，如"亚托克斯和暗裔有什么关系？""艾欧尼亚有哪些英雄？"

## 当前状态

- `documents/document.txt` = 南航介绍文档
- `documents/document_vectors_enhanced.json` = 基于南航文档构建的向量库
- `documents/lol_champions.txt` = 233 个英雄背景故事（已采集，但未入库）

## 实施方案

### 步骤 1：切换数据源

将 `document.txt` 替换为 LoL 英雄数据，同时**保留南航数据备份**：

```
document.txt       → lol_champions.txt 的内容
nuaa_document.txt  → 原南航文档备份
```

### 步骤 2：重建向量数据库

调用 DocumentManager 重建向量库：
- 分块大小：300 字符/块
- 每块生成 5 个问题向量（减少 API 消耗）
- 预估：233 个文档块

### 步骤 3：启动 Web 服务验证

用 Flask 测试客户端跑几个关系分析查询：

| 测试查询 | 预期检索到 |
|----------|-----------|
| "亚托克斯的背景故事" | 暗裔剑魔 Aatrox |
| "艾欧尼亚有哪些英雄" | 含"艾欧尼亚"的英雄 |
| "暗裔一族有哪些成员" | 含"暗裔"的英雄 |

### 步骤 4：还原

测试完成后可随时把 `nuaa_document.txt` 还原为 `document.txt` 并重建数据库。

## 影响范围

| 改动 | 类型 | 可逆 |
|------|------|------|
| `document.txt` 内容替换 | 数据替换 | ✅ 有备份 |
| 重建向量数据库 | 数据库重建 | ✅ 可重新构建 |
| **不修改任何代码** | - | - |

## API 消耗预估

- 233 个文档块 × 5 个问题/块 ≈ 约 6 万 tokens

### 分析

- **范围查询成功**：地区/阵营类查询（弗雷尔卓德、艾欧尼亚）效果较好，因为背景故事文本中包含地区名
- **精确名称匹配失败**：查询"亚托克斯"但文档中该词在"称号"标签下，e5 向量模型未能很好匹配。这是 bi-encoder 检索的固有限制
- **重排序模型加载成功**：`BAAI/bge-reranker-v2-m3` 在 CUDA 上运行，说明之前有缓存

### 改进方向（后续可做）

1. **Query 重写**：查询"亚托克斯"时自动扩展为"暗裔剑魔 亚托克斯 Aatrox"
2. **混合检索**：在向量检索基础上增加 BM25 关键词检索，弥补精确名称匹配
3. **文档格式优化**：在背景故事文本中更多重复英雄名称，提高命中率

### 还原方式

# 然后重新执行数据库重建
