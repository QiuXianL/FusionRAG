# 方案：多轮对话模式

## 目标

在现有"单次检索"基础上增加"多轮对话"能力，让用户可以和 AI 展开关于符文之地的连续对话。

## 设计

### 两种模式共存

| 模式 | 行为 | 适用场景 |
|------|------|----------|
| **检索**（现有） | 单次查询 → 检索文档 → AI 回答 | 精确查找某个英雄/故事 |
| **对话**（新增） | 多轮连续对话 → 携带历史上下文 → AI 回答 | 深入讨论、追问、对比分析 |

对话模式中每次请求仍会触发 RAG 检索（基于当前消息），同时携带最近 N 轮对话历史。

### 后端改动

新增 `/api/chat` 端点，接收：

```json
{
  "message": "他哥哥是谁？",
  "history": [
    {"role": "user", "content": "亚索的背景故事是什么？"},
    {"role": "assistant", "content": "亚索是艾欧尼亚的御风剑客…"}
  ],
  "top_k": 5
}
```

历史记录由前端维护，每次请求时发送最近 10 轮。

### 功能

- **Tab 切换**：顶部 "🔍 检索" | "💬 对话"，互不干扰
- **多轮对话**：前端维护 `chatHistory` 数组，每次请求带最近 10 轮上下文
- **对话检索**：每轮仍触发 RAG 检索 + 重排序 + 流式 AI 回答
- **消息气泡**：用户（右，金色边框）+ AI（左，贤者头像 🏛️）
- **对话参考**：右侧边栏显示当前消息的检索结果

### 对话请求格式

```
POST /api/chat
{"message": "他哥哥是谁？", "history": [...], "top_k": 5}
→ SSE stream: retrieval_start → retrieval_complete → ai_start → ai_chunk… → complete
```
